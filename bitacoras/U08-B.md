### Desviaciones y decisiones
1. **`--tmpfs /tmp` de CA-6.** Con el comando literal de la tarea el backend no arranca: Docker monta el tmpfs `noexec` y `sqlite-jdbc` extrae su biblioteca nativa a `/tmp` y la carga desde ahí (`UnsatisfiedLinkError … Operation not permitted`; `ca6-rojo-tmpfs-noexec.txt`, `espera=124`, 181 s). En Kubernetes el `emptyDir` no es `noexec`, así que el Deployment no cambia; en `ca6.sh` se usa `--tmpfs /tmp:rw,exec,nosuid,nodev`, que reproduce el `emptyDir`. Queda como candidata (abajo).
2. **U08-T06, ruta `/`:** la tarea del plan dice «`/` → front»; el front es U09 y su Service no existe, así que no hay ruta `/` (la añade U09).
3. **C-98, `curl` sin versión fija:** Alpine solo guarda la última versión de cada rama; un `curl=<versión>` rompería el build con cada parche. Se comenta en el Dockerfile. Hoy resuelve `curl 8.14.1-r2`.
4. **C-17 decidida para el backend:** UID/GID 10001 fijos y `fsGroup: 10001` con `fsGroupChangePolicy: OnRootMismatch` para que el PVC sea escribible. `CANDIDATAS.md` no se toca. Cuenta con el `emptyDir` `tmp` de 256Mi para las partes multipart de Tomcat.
5. **`apk del apk-tools`** también purga `ca-certificates-bundle` (se vio en el log); `ca-certificates` queda instalado y `/etc/ssl/certs/ca-certificates.crt` existe (comprobado).
6. **Build por digest:** `FROM` con etiqueta y digest; Docker valida el digest y usa la etiqueta solo como referencia.
7. Dockerfile de imagen del init: la etapa `revision` copia `descargar.sh` a `/descargar.sh` (no se usa la ruta final) y la etapa final lo trae con `COPY --from=revision`; así el script instalado es el que pasó `shellcheck` (`mismo-script` en CA-5).
